## Goal

Capture ideas for **AI-powered apps that do the small, recurring, non-essential
logistics tasks with little to no human input** — the improvement/support layer, not
the service-critical operations. The recurring theme across every idea: the AI rarely
starts from a blank page. It either **updates a previous version** or **derives variants
from one master**.

<Note>
  **The filter for everything here:** if the task is skipped today, does anything stop
  moving? If **no**, it's a candidate. If **yes**, it's operational and out of scope.
  Non-essential ≠ low-value — it means safe to defer, low blast radius, ideal for AI.
</Note>

## The reusable engines

Almost every idea below reduces to one of a few patterns. That convergence is a good
sign: a small number of engines can power many tools.

| Engine | Shape | Why it's AI-safe |
| --- | --- | --- |
| **Update engine** | old version + new data → new version | Prior artifact is the template; output is diffable; human approves in seconds |
| **Variant engine (basic)** | one master → text / language / format variants | Structure is fixed; AI only swaps safe content |
| **Variant engine (creative)** | one master → composited, restyled, personalized visuals | Promotional, not procedural; low blast radius; plays to generative strengths |
| **Gatekeeper / normalization engine** | messy input + a data contract → clean, validated, canonical record | Deterministic rules for format; AI only for interpretation; escalates on low confidence |

## Idea catalog

### 1. Work Instructions creator

Replace fiddling with PowerPoint. Operator captures a photo per step (Power Apps camera)
plus an optional voice note; AI writes each step into a standard template and renders the
formatted work instruction.

- **Engine:** Update (re-shoot one step → regenerate just that step, bump the version).
- **AI does well:** describe the action from the image, transcribe/clean the voice note,
  sequence and number steps, flag PPE/safety cues.
- **Gotchas:** blurry/dark photos (add a retake nudge); never let AI *infer* exact specs
  (torque, temp, part numbers) — make those confirmed fields; lock the template tightly.
- **Difficulty:** Low–Medium. Very tractable on Power Platform.

### 2. Campaign / PR image compositing (self-serve for Site Manager / BPE)

Central team publishes one hero image (e.g. Innovation Week). Each site remixes it into
their own poster / screen / banner — reframed, localized, combined with a local facility
photo, and with the **site manager or BPE composited in**.

- **Engine:** Variant (creative).
- **Maker is a non-designer** — this is the key constraint. Design for "impossible to
  make it look bad," not "powerful editor."
- **AI does well:** reframe/outpaint to new aspect ratios, blend the local photo, restyle
  to match, drop headline/site name into a locked brand frame.
- **Compositing rule for real people:** **composite** the manager/BPE (auto background
  removal + placement) so likeness stays 100% accurate; do **not** generatively repaint
  a recognizable face. Add a consent checkbox.
- **Design for the non-designer:** presets over tools, one-tap compositing, locked
  brand guardrails, 2–3 finished options to pick from, mobile-first, light/no approval.
- **Difficulty:** Medium. Generative image models fit here better than on procedural signage.

### 3. Reporting: source → document / deck / digest

Point the app at a **structured source (ideally Excel/CSV)** and generate the reporting
artifact.

- **Engine:** Update (refresh last period's report with new figures).
- **Tiers, easy → hard:**
  - **Easiest:** Excel → formatted Word/PDF report with commentary; → PowerPoint review
    deck; → "explain this sheet" digest; → scheduled Teams/email KPI digest.
  - **Medium:** template-fed Power BI refresh (a `.pbit` you built once + AI column
    mapping + AI-generated DAX measures); DAX generator from plain-English metric
    descriptions; pre-report data cleaner (dates/units/dupes/header drift).
  - **Hardest:** point at an arbitrary DB/ERP → full report (lean on Copilot in
    Power BI / Fabric here rather than rebuilding it).
- **Reality check:** auto-building a full interactive `.pbix` from scratch is the hard
  part and Microsoft already ships most of it (Copilot in Power BI / Excel). Smart move
  is to **wrap and automate around Copilot**, and use a clean Excel source to generate
  the *ingredients* (model, measures, narrative) into a template.
- **Difficulty:** Low for documents; Medium for templated Power BI; High for arbitrary sources.

### 4. Reporting & analytics — the deferrable slice

Not report generation itself, but the housekeeping/insight layer around it.

- Auto-written **variance / trend commentary** (the "so what") on numbers already published.
- **Anomaly-only report** — output just the metrics that moved unusually.
- **Exception report writer** — cluster the raw exception log by root cause, write the summary.
- **Q&A over Excel** — "cost-per-shipment for LATAM in Q2?" answered from the sheet.
- **Cross-sheet consolidator** — merge each region's Excel into one global sheet/report.
- **Commentary-only bot** — keep existing Power BI; AI just writes the monthly narrative.
- **Engine:** Update. **Difficulty:** Low–Medium (structured source assumed).

### 5. Continuous improvement (Kaizen) support

- **Idea inbox triage** — dedupe, categorize, tag staff suggestions; update the Kaizen board.
- **Living SOPs** — draft the updated work instruction when a process changes; redline what changed.
- **Root-cause draft generator** — first-pass 5-Whys / A3 from an incident log.
- **Recurring-issue detector** — surface "this problem happened 6× this month" from exception logs.
- **Lessons-learned synthesizer** — roll scattered post-incident notes into a themed summary.
- **Engine:** Update. **Difficulty:** Low–Medium.

### 6. Global management support

- **Regional roll-up consolidator** — merge regional reports into the global view, keep last format.
- **Auto-benchmarking** — rank sites/regions and write the comparison narrative.
- **Meeting-pack builder** — assemble the MBR/QBR deck from latest data in last cycle's structure.
- **Risk-register updater** — flag which risks changed status; suggest new ones from recent incidents.
- **ESG/sustainability tracker** — refresh metrics vs. prior report and draft commentary.
- **Engine:** Update. **Difficulty:** Medium.

### 7. Variant / communications helpers

- **One master → text/language/format variants** — signage, OPLs, labels, screen slides.
- **One SOP → role-specific cut-downs** — operator short version vs. supervisor full version.
- **One update → audience variants** — floor toolbox-talk vs. manager email vs. notice-board line.
- **One report → tiered summaries** — exec headline / manager summary / full pack.
- **Base label → per-SKU/per-bin batch** — one design, populated from a list, print batch out.
- **Language-sync watcher** — when a master changes, flag and regenerate every stale variant.
- **Engine:** Variant (basic). **Difficulty:** Low–Medium.
- **Note:** for exact-text/brand signage, **template + AI content-swap** beats pure image
  generation. Reserve generative image work for annotation and creative campaign assets.

### 8. Data validation & cleansing gate (before OneData)

Master data is supposed to follow clear contracts (contract IDs = 3 letters + 5 digits,
site IDs = 3 letters + 3 digits, customer = brand vs. parent customer = contract owner),
but BD people enter freeform mess like "nike SA Turkey bla bla." This tool validates and
cleans records **before** they land in the OneData database. Highest-leverage idea,
because bad master data quietly corrupts every downstream report and document.

- **Engine:** Gatekeeper / normalization.
- **It's a hybrid — split the problem:**
  - **Format rules** (ID patterns) → deterministic regex/rules. 100% reliable, no AI.
  - **Interpretation** (parse "nike SA Turkey" into fields) → AI.
  - **Entity resolution** (customer/brand vs. parent/contract owner) → match against the
    master list; AI disambiguates.
- **The "data contract" document does double duty:** written once as structured rules
  (field → format → good example → bad example → fix), it both **educates BD people** and
  **is the ruleset the AI enforces.** One source of truth.
- **Hard requirement:** the AI must **match against the real master list, never invent a
  canonical entity.** Can't confidently match → flag for a human, don't guess.
- **Placement:** primary = pre-submit validation (Power Apps form / OneData entry wrapper),
  shift-left at the source; bonus = batch cleaner over existing OneData, ranked by confidence.
- **Gotchas:** suggest with before→after + confidence, don't silently "fix"; high-confidence
  auto-apply, low-confidence → human; keep an audit trail; learn from human overrides.
- **Difficulty:** Low–Medium (format), Medium (entity resolution against master data).

## Design principle: build for the non-designer maker

Several of these tools are operated by site managers / BPEs, not specialists. That flips
the priority from capability to guardrails:

- **Presets over tools** — no canvas, no layers; pick format, drop input, type a line.
- **One-tap compositing / generation** — the hard steps happen automatically.
- **Locked brand guardrails** — logo, colors, fonts, master asset can't be broken.
- **"Good by default" + a few options** — choosing beats creating.
- **Mobile-first** — they're on the floor with a phone.
- **Confidence to publish** — on-brand-by-construction + low risk → light or no approval.

## Microsoft / Power Platform stack notes

The natural home for most of these (keeps data in-tenant, respects governance):

- **Capture / UI:** Power Apps (camera, forms, mobile).
- **Orchestration:** Power Automate (triggers, scheduling, routing).
- **Storage:** SharePoint / Dataverse (masters, versions, outputs).
- **AI:** AI Builder for simplicity, or Azure OpenAI (incl. vision / image) for control
  over model and prompt; Copilot in Power BI / Excel / Fabric for the reporting-heavy ideas.
- **Output:** Word/PDF/PowerPoint templates; `.pbit` for templated Power BI.

## Difficulty & prioritization snapshot

| Idea | Engine | Difficulty | Best first bet? |
| --- | --- | --- | --- |
| Data validation gate (before OneData) | Gatekeeper | Low–Med | ★ highest leverage (fixes root cause) |
| Excel → document/deck/digest | Update | Low | ★ strong beachhead |
| Work Instructions creator | Update | Low–Med | ★ high-pain, tractable |
| Variance / anomaly commentary | Update | Low–Med | good add-on |
| Campaign image compositing (self-serve) | Variant (creative) | Med | ★ clear user + low risk |
| Kaizen idea triage / living SOPs | Update | Low–Med | good add-on |
| Global roll-ups / benchmarking | Update | Med | later |
| Templated Power BI refresh | Update | Med | after documents work |
| Arbitrary source → full Power BI | Update | High | lean on Copilot |

**Sweet spot for a first build:** structured Excel source → generated document, and/or
the compositing tool (clear non-designer user, low blast radius). Both are low-input,
diffable/on-brand-by-construction, and never stop the service.
